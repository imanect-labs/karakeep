# feat(recommender): collection primitives — URL 正規化・取り込み配分・重複判定・クラスタリング・ソースアダプタ

- 作業日時: 2026-08-07
- 対応フェーズ: Phase 1 統合実装 / B. 候補収集（前半）

ワーカーを書く前に、判断が入る部分を純粋関数として切り出してテストで固めた。
ワーカー側は DB とキューの配線だけになる。

## 対応内容

### `url.ts` — URL 正規化と重複キー（FR-C-04）

同じ記事が RSS・HN・アグリゲータから別々の URL で流れてくる。正規化しないと
候補プールが同じ記事で埋まり、多様性制約も意味をなさなくなる。

- http → https、`www.` 除去、末尾スラッシュ、フラグメント、既定ポート
- トラッキングパラメータの除去。**ここは意図的に保守的にした**。`utm_*` 等の
  既知のものだけ消し、知らないパラメータは残す。`?p=123` のような CMS の
  パーマリンクを巻き込むほうが害が大きい
- `si` のようにサイトによって意味が変わるパラメータはホスト単位で判定する
- AMP（パス・サブドメイン・Google AMP キャッシュ）を元ページに寄せる
- 残ったパラメータはキー順に並べ替える。順番違いを別 URL にしない

`domain` は eTLD+1 ではなくホスト名そのものにした。Public Suffix List を
持ち込むコストに対して、この用途 —「どのサイトを購読するか」— では
`blog.example.com` と `shop.example.com` を**区別したい**ことのほうが多い。

### `intake.ts` — 日次取り込み配分（FR-C-03 / FR-D-16 / FR-D-16b）

設計上いちばん効く歯止め。取り込みを 400 件で固定し、ドメインの事後平均で
配分することで、候補プールのサイズをドメイン数から切り離す。

- 配分は **D'Hondt 方式（最大商法）**。1 件ずつ `weight / (割当済み + 1)` が
  最大のバケットへ渡す。比例配分がそのまま出て、上限超過が構造的に起きず、
  端数処理の恣意性も入らない
- プロフィール非依存の 20% は**先に確保してから**残りを配る。後から帳尻を
  合わせる方式だと、事後の高いドメインが強い日に下限を割る
- ただし非依存ソースが枯れている日に枠を空けたままにはしない

実装中に 1 つ設計を足した。**重みに下限 0.01 を置いた**。事後平均が 0 に
張り付いたドメインの取り込みが完全に止まると、新しい記事が入らず、事後が
更新されず、良くなったかを二度と確かめられない状態で購読席だけ占め続ける。
悪いドメインを追い出す仕組みは降格（FR-D-15）であって兵糧攻めではない。

### `dedupe.ts` — 同一記事の検出（FR-C-05）

手がかりを 3 段構えにした。URL → タイトル → 埋め込み近傍。

**埋め込み近傍だけに頼らないのが要点。** コサイン 0.93 は「同じ話題の別記事」
も拾ってしまう閾値で、それを重複として潰すと候補プールの多様性が落ちる。
URL とタイトルで取れるものはそちらで取る。

重複の連鎖（b が a の重複、c が b の重複）は終端まで解決してから記録する。
そうしないと後段で代表の candidate が引けない。

計算量は `新規 × (新規 + 既存)`。1 日 400 件 × プール 5,000 件で約 200 万回の
内積になるが夜間バッチなので許容し、プール全体の総当たりはやらない。

### `cluster.ts` — 球面 k-means（FR-S-04 / FR-S-05）

ベクトルは L2 正規化済みなので、距離ではなく内積で回す。

**クラスタ ID の連続性が肝**。前日の重心を初期値に渡すと「クラスタ 12 =
推薦システム」というラベルが日をまたいで生き残る。ここが崩れると UI の
「興味の現在地」も学習の特徴量 6・7 も毎日意味が変わる。テストで固定した。

空クラスタは潰さず、いちばん重心から遠い点を種にして生き返らせる。潰すと
クラスタ ID がずれて連続性が壊れる。

`clusterPreferenceScore` はベータ平滑化。生の正例率だと提示 1 件・正例 1 件の
クラスタが選好度 1.0 になって上位を独占する。

### `sources/` — 収集元アダプタ（FR-C-01 / FR-C-02）

`rss` / `hn` / `arxiv` / `github` を実装。`fetch` を注入する形にして、テストを
ネットワークから切り離した。

- **rss** — 既存 `feedWorker` と同じ `rss-parser` を使うが、ブックマークは
  作らない。取得を `parseURL` に任せず自前 fetch にしたのは、連絡先入りの
  User-Agent と AbortSignal を通すため。日付を出さないフィードのエントリは
  `since` で捨てない（捨てると永久に候補に入らない）
- **hn** — Algolia の `search_by_date`。`search` は関連度順で日次収集に向かない。
  本命は D4 の「ドメインの標本」としての用途
- **arxiv** — 汎用パーサに通さず自前で読む。arXiv の Atom は `<summary>` に
  アブストラクト全文を入れる独自の使い方をしていて、汎用パーサでは要約と
  本文の区別が付かない
- **github** — `github.com/trending` の HTML スクレイプではなく公式の検索 API。
  実用上ほぼ同じものが得られて壊れない。鮮度は `created_at` ではなく
  `pushed_at`（再活性化したリポジトリを拾える）

未実装の `scrape` / `custom` はレジストリが null を返す。呼び出し側は
「そのソースを飛ばす」として扱い、1 ソースの欠落で収集全体を止めない。
