# Briefing の画像表示・明示的な翻訳・ページ送り

- 作業日時: 2026-11-09
- 英語記事に「日本語に翻訳」を表示し、タイトルと紹介文を翻訳する。原題も残す。
- 翻訳後は既存の本文翻訳リーダーへ進める。翻訳だけでは保存の正例を作らず、
  中立の `read_intent` を記録する。リーダーのタイトルも訳題にするが、編集済みの名前は保つ。
- OGP / Twitter 画像を非同期取得し、画像付きカードにする。画像が無い・壊れている場合も
  同じ比率の代替表示にして読み進められるようにする。
- ページ送り・日付変更・Briefing への入場時に PC の main とモバイルの window を先頭に戻し、
  記事一覧にフォーカスを移す。画像や翻訳の更新ではスクロールを戻さない。

## サーバー

DB migration `0097` は共有キャッシュの画像 URL・取得日時と、候補の翻訳要求日時を追加する。
既存の Briefing も取得時に画像ジョブを投入するため、再ランキングは不要。
画像取得は SSRF 対策済みネットワーク経由で、6 秒・2 MiB・5 件ずつ。失敗は 1 日、画像は
7 日キャッシュする。共有キャッシュへの書き込みは公開収集記事に限る。

翻訳は設定済み推論クライアントを使い、旧ダイジェスト生成を有効にはしない。
所有者を確認して要求を原子的に確保し、連打を抑止する。失敗・5 分経過の要求は再試行可能。
翻訳中と画像取得中は最大 2 分ポーリングする。閲覧イベントは大きくなったカード全体ではなく、
見出しが 50% 以上・1 秒以上見えたことを確認して記録する。

## 確認

- Worker: HTML 解析、5 件単位の継続、キャッシュ、所有者境界、翻訳保存、エラー処理をテスト。
- tRPC: 画像取得で推薦履歴が変わらないこと、二重要求、タイムアウト再試行、所有者境界、
  訳題の採用とユーザー編集の保持をテスト。
- Shared: 言語判定、翻訳 JSON、入力長制限をテスト。
- ローカルの隔離 DB・翻訳スタブで UI → API → キュー → Worker → カード更新を確認。
  翻訳後のイベントは `read_intent` と `viewed` のみで、`saved` は付かない。
- PC 1280px とスマホ 375px で画像の代替表示・横はみ出し・日付変更・ページ送りを確認。
  PC / スマホともスクロール位置が 0 になり、記事一覧にフォーカスする。
